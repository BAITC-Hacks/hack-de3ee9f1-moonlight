# Beeline Tariff Marketing Campaigns — Agent

## Краткое описание

Агент для трека «Beeline Tariff Marketing Campaigns Case». Решает задачу выбора
до 10 тарифных маркетинговых кампаний (сегмент абонентов → целевой тариф →
канал коммуникации) в рамках ограниченного бюджета (100 000 у.е.) и лимита
охвата (15 000 контактов), максимизируя чистый прирост ARPU. Пользователь —
аналитик маркетинга, который получает от агента готовый план кампаний вместо
ручного перебора гипотез.

## Что реализовано

- Построение приорной оценки эффекта перехода между тарифами по исторической
  выборке (`data/change_tariff.csv`).
- Ранжирование кандидатов (текущий тариф → целевой тариф, ARPU-сегмент) по
  приору и размеру/ценности сегмента в текущей аудитории.
- Назначение канала коммуникации под ценность сегмента (HIGH → call,
  MID → digital_ads, LOW → sms) до проведения пилота.
- Проверка топ-кандидатов реальными пилотами (`env.run_pilot`) с учётом
  остатка бюджета и лимита пилотов.
- Байесовское сглаживание приора и наблюдённого в пилоте эффекта (вес
  наблюдения растёт с размером пилота).
- Жадный отбор финальных кампаний по чистому эффекту на абонента без
  пересечения по сегментам, с учётом остатка бюджета/охвата.
- Fallback-сценарий: если ни один пилот не подтвердил прибыльную связку,
  агент возвращает несколько кампаний по приору на бесплатном канале (push),
  чтобы не сдать пустой список.
- Обработка ошибок: весь основной цикл обёрнут в `try/except`, при сбое
  возвращаются уже накопленные кампании, а не пустой результат.

## Как работает решение

1. Строится приорная модель эффекта по `data/change_tariff.csv`.
2. Кандидаты (тариф → тариф, сегмент) ранжируются по приору × размеру
   аудитории, каждому назначается канал.
3. До 14 лучших кандидатов проверяются пилотами на 150 абонентах.
4. Наблюдённый эффект комбинируется с приором (сглаживание по размеру пилота).
5. Кампании с положительным ожидаемым чистым эффектом сортируются и жадно
   набираются в план (до 10 штук, без повторного использования сегмента),
   пока не исчерпан бюджет или охват.
6. Агент возвращает список из ≤10 кампаний в формате, ожидаемом средой.

## Технологии

- Python 3
- pandas, numpy — обработка данных и агрегации
- Интерфейс среды соревнования (`environment.py` / `mock_environment.py`,
  выданы организаторами)

## Архитектура

Один класс `Agent` с методом `act(env)`:

- `_build_prior()` — приорная модель из истории смен тарифов
- `_rank_candidates()` — ранжирование и назначение канала
- `_select_campaigns()` — байесовское сглаживание + жадный отбор
- `_fallback_campaigns()` — запасной план на случай неудачной серии пилотов

Компоненты вызываются последовательно внутри `act()`, промежуточный результат
сохраняется в `self._partial_campaigns`, чтобы при исключении вернуть то, что
успели насчитать, а не пустой список.

## Установка и запуск

```bash
pip install pandas numpy
python local_eval.py              # один прогон на мок-среде
python local_eval.py --runs 10    # проверка устойчивости на 10 seed
python make_submission.py         # генерирует submission.csv
```

Агент запускается из каталога кейса (рядом должны быть `agent.py`,
`environment.py`, `mock_environment.py`, `scoring_core.py`, `data/`,
`customer_profile.csv` — файлы, выданные организаторами).

## Как проверить решение

1. Выполнить `python local_eval.py --runs 10`.
2. В выводе проверить блок «устойчивость по прогонам»: количество прогонов
   в плюс из общего числа и разброс между медианой, минимумом и максимумом.
3. Выполнить `python make_submission.py` и убедиться, что `submission.csv`
   создан и содержит от 1 до 10 корректных кампаний.

На мок-среде (условные, не судейские эффекты) решение стабильно даёт
положительный чистый результат на всех проверенных seed.

## Данные и интеграции

Используются только данные, выданные организаторами кейса:
`customer_profile.csv`, `data/change_tariff.csv`, `data/dict_tariff.csv`.
Внешние API и сторонние сервисы не используются — вся логика работает
оффлайн поверх среды `environment.py`.

## Известные ограничения

- Размер пилота фиксирован (150 абонентов) — не адаптируется по ходу
  разведки к уже накопленной уверенности.
- Канал для кампании назначается заранее по фиксированной эвристике
  (сегмент → канал), а не подбирается перебором нескольких каналов на
  одном сегменте.
- Приорная модель не учитывает дисперсию исторической оценки — только
  среднее значение и количество наблюдений.
- Fallback-сценарий (без пилотов, канал push) рассчитан на приорную оценку
  и может быть менее точным, чем основной сценарий с пилотами.
